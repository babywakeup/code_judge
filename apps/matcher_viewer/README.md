# SD-1 matcher 批量推理工作台

参考 AOI 软件的筛选侧栏、密集卡片图库和当前页批量操作。独立于现有标注浏览器和单图桌面查看器，直接调用 Python matcher 的原有配置推理入口和结果渲染器，无额外 Web 框架依赖。

## 启动

在仓库根目录、已安装 matcher 依赖的 Python 环境运行：

```powershell
.venv/Scripts/python.exe -m apps.matcher_viewer
```

默认浏览器地址 `http://127.0.0.1:7876`。启动只扫描，不自动对整个数据集推理。

当前工作区已添加 VS Code 任务 **PTM: matcher gallery**，也可从「终端 → 运行任务」启动。该任务位于本地 `.vscode/tasks.json`（仓库默认忽略 `.vscode/`）；其他机器可直接使用上述模块入口。

- 图片：`source/SD-1/imgs`，递归扫描 jpg/jpeg/png/bmp/webp。
- 配置：`periodic_template_matcher/config.sd1.labelme.opencv.json`。
- 新结果：`periodic_template_matcher/results/sd1_gallery`。
- 默认尝试读取已有 `sd1_opencv` 单图结果，只有清单目标路径对应源图且导出 input 像素与源图完全一致时才关联。历史结果不会被改写。

可用参数：`--images`、`--config`、`--results`、`--port`、`--host`、`--no-browser`。`--import-result` 可重复指定已有单图结果目录或清单；它不是递归扫描任意历史实验目录，避免误导入 anomaly/evaluation 等结果。

## 操作

1. 左侧按目录类别、matcher 状态、模板、工位、文件名严重度、日期、关键词或最低匹配分数筛选；可按匹配分数排序。
2. 默认每页 **80 张、5 列**；每页可选 40/80/120/200 张，列数可选 4/5/6/8。窄屏自动减列。图片懒加载，仅取缩略图，已加载预览有有界内存缓存。
3. 点击「匹配本页」，或先勾选部分图片；「匹配全部筛选」会确认范围数量，后台逐张处理并轮询更新进度。默认跳过当前配置的完整缓存，导入的历史结果仍可按当前配置推理。取消跳过可强制重跑。单图异常不终止后续图片。
4. 「停止」在当前图片完成后停止队列，不强行打断 OpenCV。退出服务也会等当前图片完成。重新启动后再运行会跳过相同配置/源图的完整缓存，失败或中断项可重试。
5. 图库可切换原图、标签叠加、掩膜、并排对照；可调透明度，查看直接迁移、周期补全和对象支持图层，显示未知区域。
6. 点击图片打开详情，查看模板、分数、覆盖率、输入有效区、类别像素数和完整 matcher 元数据。预览和无损下载使用原图尺寸，便于对照裁剪前后的坐标。左右方向键切换当前页图片，Esc 关闭；高清放大支持拖动和滚动。
7. 「重新扫描」发现新增图片和已有缓存。修改配置或模板文件后请**重启服务**，以建立新的配置快照。

### 重叠掩膜查看

新结果分别保存直接匹配、周期补全、独立对象三套掩膜及有效区，允许同一像素属于不同来源的
不同类别，不因最终 label=2 覆盖 label=1 而删除直接层/补全层。默认“全部来源（重叠混色）”，
可单独切换三层；“最终互斥标签”仍显示原单通道预测。详情类别统计仍按最终互斥标签计算，
各独立层可分别无损下载。重叠是待检查的多份匹配证据，不代表所有冲突假设都正确。
启用独立对象匹配时，其类别（当前 label=2）只从对象层显示，直接层和语义补全层不复制该类。

旧结果未保存这些层时沿用旧显示，无法事后反推原始掩膜。**重启服务、刷新页面并取消
“跳过已完成”后重算相关图片**；代码变更不自动改变旧缓存签名，不会覆盖历史目录。

## 判定含义和缓存边界

- **匹配通过 ≠ 无缺陷，匹配未通过 ≠ 有缺陷**。这里展示配准验收与标签迁移结果，没有额外执行 anomaly、GraphCut 或 SAM3。目录类别与严重度来自原始数据命名，不是 matcher 预测。
- 可用标签、匹配拒绝、缺少模板标注、运行异常和未运行分别展示，拒绝时不会显示预测掩膜；标签 0 和未知区域继续由独立 validity 区分。
- 文件名严重度和工位按当前 SD-1 的 10 段命名解析；不符合命名的图仍可浏览，但相关筛选字段为空。
- 配置中的 `target` 被逐图替换，模板路径转换成绝对路径。`options.step1` 的四个有效区边界随配置传给 Python Matcher，由 Matcher 在缩放、配准与补全前统一裁剪。SD-1 默认保留全宽和 `Y [0, 1891)`，终点 `null` 取对应图像边界。旧配置的 `target_valid_height` 仍可用。批量配置可使用公用有效区边界，单图 `target_valid_mask` 会被拒绝。
- 缓存签名包含配置内容、模板/标注/有效区文件内容以及源图路径、大小、纳秒修改时间。若外部工具改变源图内容却刻意保留大小和修改时间，需要取消「跳过已完成」强制推理。
- 每次推理写入新的唯一目录，最后才发布 receipt；失败输出不作为完整缓存。重跑保留旧版本，可能逐渐占用磁盘。已导入历史结果是冻结输出，并非当前配置的认证缓存；完整元数据和结果路径可核验其来源。
- 本地回环默认绑定、操作令牌与 Origin 校验、防目录穿越。不要绑定公网或作为多用户生产服务使用。

## 验证

新运行的耗时覆盖输入准备、推理和结果 JSON 导出，扣除 PNG 编码与写盘。界面按记录区分计时口径。历史性能数据见 `docs/single_image_performance.md`。

当前 SD-1 配置显式启用 `options.step3.ecc_roi: true`：对于局部有效区，ECC 在带边距的
原分辨率窗口中迭代，异常或变换越过人工窗口时回退整图；不减少候选数、迭代上限或验收阈值。
这是允许浮点/标签差异的加速模式，不保证旧输出逐位相同。需要原整图 ECC 时改为 `false`
并重启服务。通用 MatcherConfig 默认关闭此选项。新旧输出的耗时、标签 IoU 和有效区差异
可用 [tools/benchmark_ecc_roi.py](../../tools/benchmark_ecc_roi.py) 交替验证；详见
[性能说明](../../docs/single_image_performance.md)。缓存中的历史耗时不会因代码更新自动重算。

SD-1 同时启用 `options.periodic.shared_periods: true`（通用 API 默认关闭）：类别 1 复用
x/y 格点，类别 2 仅沿源图 y 复用同身份周期。模板/目标自平移验证通过后共享周期几何，
不再逐副本仿射 ECC；不可信周期回退原校验。倾斜后的目标周期保留源轴权限，各新增区域
仍独立验证可见证据，不按 ABCD 水平平铺身份。新旧标签允许变化，并非逐位等价。
可用 [共享周期对照工具](../../tools/benchmark_periodic_sharing.py) 在保持 ROI 配置不变时
串行比较关闭/开启的耗时、标签 IoU、身份及有效区差异。修改开关后需重启服务。
